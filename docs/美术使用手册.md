# 美术视觉审查工作台 · 使用手册 V1.1

适用：UI 美术、UI/UX 设计、主美及评审人员。基于现有工作台 V1.1；检查单张竖屏游戏 UI 的视觉表达，而不是替代全流程 UX 测试。

[打开工作台](https://baijingxuan99-rgb.github.io/UX-Specification/visual.html)

## 01 / 快速开始

每个页面只解决一个问题：玩家能否快速看懂当前目标、做出正确决策，并找到对应的操作？

1. **准备截图**：导出一张完整的竖屏 UI，建议使用与项目设计稿一致的分辨率。文件支持 PNG、JPG、WebP，小于或等于 30 MB。优先使用真实页面内容，不用空白占位稿。
2. **打开审查入口**：进入 UX Lab → 左侧「美术视觉审查」，点击上传区或将图片拖入。页面显示文件名和原始尺寸。
3. **填写设计意图**：右侧选择页面类型，填写页面名称、玩家此刻的核心目标、预期第一视觉焦点。先定义功能，再判断视觉，不要根据当前最亮的区域倒推重要性。
4. **标注核心区域**：填写元素名称，选 L1–L4 层级，在截图上按住拖出矩形。至少标记一个 L1 和一个非 L1；建议覆盖关键决策信息和最抢眼的装饰。
5. **检查与记录**：依次切换原图、灰度、模糊、显著性，阅读自动诊断；在18项视觉 UX 自查中填写结论和备注。
6. **修改与交付**：将具体修改动作写入「修改与复测」，导出 Markdown 报告及 JSON 标注；在设计软件完成调整，再上传第二张图进行对照。

## 02 / 视觉层级怎么划分

L1–L4 是业务重要性标签，不是亮度、面积、颜色或评分的硬性规定。与原工作台 L1/L2/L3 测试分层不是同一个概念。

| 层级 | 判断依据 | 常见元素 | 设计方向 |
| --- | --- | --- | --- |
| L1 核心 | 玩家首先需要看懂或执行什么？ | 挑战、升级、结算结果、关键生存提示 | 形成明确焦点；必要时多个核心并存 |
| L2 决策 | 操作前必须读懂什么？ | 价格、消耗、属性变化、条件、血量 | 可读、成组、靠近相关操作；不被遮挡 |
| L3 辅助 | 需要时才查找什么？ | 返回、筛选、帮助、次要入口 | 稳定易找，但不抢占核心 |
| L4 装饰 | 移除后是否仍能完成任务？ | 背景、纹理、光效、纯展示角色 | 保留风格与氛围，控制竞争 |

## 03 / 不同页面如何选择焦点

切换页面类型后，右侧会显示相应提示。下表用于起步，不替代实际策划规则；例如材料不足时，获取材料可能由 L3 上升为 L1。

| 页面类型 | L1 候选 | L2 候选 | 重点避免 |
| --- | --- | --- | --- |
| 主界面 | 当前主线、开始挑战 | 关卡、重要资源与状态 | 活动、红点、特效抢主目标 |
| 养成详情 | 升级、突破 | 消耗、持有量、属性变化与条件 | 角色展示强于操作；消耗难读 |
| 列表 / 背包 | 选中目标、主要批量操作 | 品质、数量、属性 | 满屏同等强调；选中不明显 |
| 战斗 HUD | 生存提示、即时操作 | 血量、波次、倒计时、技能 | 华丽动效遮挡战况 |
| 奖励 / 结算 | 结果、下一步 | 实际获得奖励及数量 | 随机奖励误显示为已获得 |
| 商城 / 确认弹窗 | 购买或取消的明确选择 | 商品、币种、价格、限制 | 促销掩盖价格；弱化取消 |
| 其他 | 由当前任务决定 | 由决策所需信息决定 | 先套模板再定义目标 |

## 04 / 框选和五种检查模式

1. **准确框选**：先选名称和层级再拖动矩形。尽量贴合元素边界，不要把大片背景或其他按钮纳入同一框；同类元素应采用类似的框选粒度。框选后右侧可以改名称、改层级、删除；撤销只移除最后一个标注。
2. **原图**：确认整体美术效果、文字、按钮和功能归属。隐藏标注后观察正常阅读路径；不要因为某元素属于 L3 就把它做得难以寻找。
3. **灰度**：去除颜色差异，观察明度层级、选中态与关键文字是否仍能辨认。灰度可帮助发现问题，但不能替代实际对比度测量或色觉测试。
4. **模糊**：弱化细节，观察大色块、主次关系、构图重心。如果装饰大色块先于目标被注意，尝试降低背景或光效的对比。模糊模式不适合检查小字。
5. **显著性**：热图显示相对像素响应，暖色与较强响应相关。对照框选元素和设计意图检查潜在冲突；它不是眼动热图，也不会自动识别按钮、文字或业务目标。
6. **双图对照**：点击「双图对照」选择优化后的截图。左侧保留原图及标注，右侧展示第二张图；再次点击该模式可换对比图。双图模式不能新建框选。若要对优化图重新量化分析，先导出旧报告，再用「更换截图」载入新图并重新标注。
7. **辅助线**：勾选安全区示意或九宫格检查边缘和构图；安全区使用上下约6%、左右约4%的示意范围，不是设备真实安全区。

## 05 / 怎样解读自动诊断

算法以局部边缘、亮度偏差和颜色差为输入，按当前图第95百分位归一化。框选区域会显示相对显著指数（0–100）、高响应像素比例及面积占比。只用于本图的辅助比较，不是通过分数或玩家注意概率。

| 诊断提示 | 触发逻辑（当前版本） | 美术处理方向 |
| --- | --- | --- |
| 整体像素变化较弱 | 全图响应 P95 小于 0.06（算法内部参考值；零响应存在回退） | 检查局部文字、按钮与背景，确认是否是有意低对比风格 |
| 没有标注 L1 / 缺少非核心 | 标注集合中缺核心或对照区域 | 补齐设计意图和代表性框选 |
| 辅助/装饰可能与核心竞争 | L3/L4 指数达到最强 L1 指数减4或更高 | 降低次要区域对比、饱和度、纹理；强化主操作独立性 |
| 关键决策信息可能偏弱 | L2 指数比最强 L1 低超过25 | 核对价格、条件、收益的字号、留白、分组和明度 |
| 核心/决策元素接近边缘 | L1/L2 超过示意安全区边界 | 留足空间，按真实设备复核 |
| 标注了多个 L1 核心 | L1 超过3个 | 检查是否可收敛；战斗 HUD 等允许合理多核心 |
| 未发现明显 L3/L4 指数竞争 | 已框选核心及非核心，未触发竞争规则 | 只代表当前标注未触发此规则，继续人工检查 |

> 不要通过故意增加噪点、光效或描边来追求指数；不要跨图比较归一化数值或把阈值当项目硬性验收标准。

## 06 / 18项规范检查：发现问题就知道怎么改

在右侧「视觉 UX 自查」逐项判断当前截图。下表把原有 UX 用例转成可执行的美术检查动作。

| 编号 / 检查项 | 检查动作 | 优化方向 |
| --- | --- | --- |
| I19 主焦点明确 | 缩小或模糊后先看哪里？是否对应目标？ | 拉开核心与装饰的明度、面积和独立性 |
| I01 核心入口与导航 | 标题、所在系统、主入口能否快速识别？ | 强化主次；固定常用入口位置 |
| I11 按钮状态 | 当前可用、禁用、选中状态是否清楚？ | 明度、描边、图标、文字联合区分 |
| I04 页签选中态 | 当前页签是否一眼可见？ | 强化选中指示，降低非选中竞争 |
| I20 资源与价格 | 金额、单位、消耗、余额能否对应？ | 成组对齐；价格贴近相关操作 |
| I21 属性与数值对比 | 前后属性能否逐项比较？ | 统一对齐、单位、增减符号；不只依赖颜色 |
| I22 图标与术语 | 陌生图标及名称是否可理解？ | 补短标签；统一同义图标及文案 |
| I23 奖励状态 | 预期、随机、已获、可领是否区分？ | 用状态文案、数量和表现准确表达 |
| I15 红点干扰 | 非关键红点是否抢占注意？ | 降低无意义高亮；动态规则待验证 |
| I16 关闭与取消 | 退出、取消、确认是否易找易区分？ | 稳定位置；拉开高风险按钮间距 |
| I18 高风险操作 | 价格、对象、后果、取消是否清楚？ | 不得为了突出购买而弱化成本或风险 |
| I06 触控尺寸与间距 | 可见按钮是否过密？ | 扩大真实热区、留间距；真机验证 |
| I07 高频操作位置 | 高频操作是否方便单手触达？ | 优化位置；实际握持待真机 |
| I24 边缘与安全区 | 标题、返回、主操作是否贴边？ | 增加安全留白，按设备适配 |
| I25 文本与密度 | 长文、大数是否遮挡或截断？ | 统一字级、行距、对齐；补极端状态 |
| I28 对比与可读性 | 灰度下关键状态与字仍能分辨？ | 局部明度对比，增加非颜色线索 |
| S01 加载状态 | 能否区分加载与空白？ | 补加载反馈；未展示则待补状态 |
| S02 空状态 | 无内容时有原因和下一步吗？ | 清楚说明；提供可执行入口 |

## 07 / 审查结论怎么填

| 状态 | 适用情况 | 记录要求 |
| --- | --- | --- |
| 未检查 | 尚未检查该项 | 不要默认为通过 |
| 通过（当前图） | 截图可见部分满足要求 | 只代表当前截图，不代表交互通过 |
| 需优化 | 存在明确的视觉问题 | 写位置、现象、影响、修改动作 |
| 待补状态/实机 | 单图不具备判断所需状态或交互 | 记录需补图、原型或设备测试 |
| 不适用 | 该页确实不包含该功能 | 填写原因；否则不计入已确认 |

> 例如没有展示加载或空状态，但实际页面存在加载过程，应标记待补状态/实机，而不是直接判为不适用。

## 08 / 实例：功法升级页

以下为演示场景，不是真实截图检测结果。假设玩家有足够材料，希望先理解收益，再升级激流咒。

1. **示例问题记录**：I19 / 功法图标周围的光效比升级区域更突出，玩家可能先关注展示而不是行动。调整：降低光效明度和纹理密度，提高升级按钮独立性。
2. **复测方法**：上传调整图，双图对照；在原图、灰度、模糊视图验证目标、决策信息、操作的关系。重新量化前先导出旧报告，然后重新框选新图。材料不足、请求中、满级等状态另行检查。

| 元素 | 预期层级 | 假设问题 | 修改动作 |
| --- | --- | --- | --- |
| 升级按钮 | L1 | 按钮较小，和背景颜色接近 | 扩大按钮视觉面积，增强独立明度和留白 |
| 伤害 120% → 135% | L2 | 小字、前后属性难比较 | 对齐数字，强调增量并明确单位 |
| 悟道石 120/100 | L2 | 消耗与持有量不易区分 | 明确持有/需要含义，靠近升级按钮 |
| 返回、获取途径 | L3 | 次要按钮和主按钮同样醒目 | 降低次要样式权重但保持易发现 |
| 功法光晕 / 背景 | L4 | 高亮大面积抢占主按钮 | 降低光晕亮度、饱和度或覆盖面积 |

## 09 / 交付与复测要求

建议将下列要求作为团队的美术自查交付约定，不是工具自动强制门槛。

- 页面名称、类型、版本（可写在页面名称或备注）、玩家目标、预期焦点填写完整。
- 至少一个 L1 和一个非 L1；关键决策信息、最强装饰已按实际情况标注。
- 相关18项已判断；不适用有原因，动态问题列入待补状态/实机。
- 问题备注包含位置、问题、玩家影响、修改动作；高风险费用、取消、关键状态优先解决。
- 修改前后截图分别保存；导出 Markdown 报告和 JSON 标注数据，报告与截图使用一致的页面/版本命名。
- 复测结论基于实际修改图；必要时交给策划/UX/QA，在原82条用例中验证真实行为。

> 当前版本只导出 Markdown 和 JSON；导出文件不含原图，没有 JSON 恢复导入、跨会话自动保存或自动同步到原工作台的功能。更换原图会清除框选，但不会自动清空设计意图、自查结论及备注；开始另一个页面时请先导出，再刷新页面重新填写。

## 10 / 使用边界与常见问题

1. **能否扔入图片自动判定全部UX？**：不能。当前是本地像素分析和人工规则辅助，不理解业务语义、不识别文字、不自动重绘。玩家目标、区域层级与检查结论由审查者确认。
2. **为什么装饰指数高不一定是错？**：细碎纹理和色差可能推高响应；有些展示页面的核心本来就是角色。依据真实任务、原图及灰度模糊表现判断，不按数值机械排名。
3. **为什么看起来小的按钮仍需真机？**：截图不是实际触控区域。iOS 44pt、Android 48dp 是原规范中的参考，不是设计稿像素；真实尺寸、手势和安全区需实机确认。
4. **为什么报告没有截图？**：图片仅本地处理，没有随报告上传或打包。请单独保存截图。刷新、关页会丢失本次审查数据；导出前不要关闭页面。
5. **能否直接共享团队记录？**：当前没有共享数据库，也不自动写回 GitHub；报告和截图应使用团队认可的内部渠道。仓库公开，请勿上传敏感素材。
